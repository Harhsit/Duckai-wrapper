How to use your API key

Reach this server — online or local

This wrapper is a server. Your website, Android app, or another server does not need the wrapper's code — it only needs this server's address (base URL) plus a valid API key, and it sends requests over the internet (or your local network) to the chat endpoint.

  • Online server (always on, no computer needed): https://duckai-wrapper.vercel.app — this live deployment on Vercel. Dashboard: https://duckai-wrapper.vercel.app/dashboard · Chat endpoint: POST https://duckai-wrapper.vercel.app/api/chat. Use this address in your Android app or external site, exactly like using the OpenAI or Claude API address.
  • Local server (your own computer): run the wrapper yourself and use http://localhost:3000 (or your computer's network address + port) as the base URL instead. Everything below works the same — only the address changes, and the examples on this page automatically use whichever address this page was opened from.

Two kinds of key — which one to use

  • Fixed key (use this on the online/Vercel server): one permanent key, set on the server as the DUCK_AI_API_KEY environment variable. The server never forgets it — it survives restarts and redeploys. The admin can see and copy it any time: open the Create API Key tab, log in as admin, and use the Fixed API key panel (Show / Copy). Put that key in your app or site's backend as shown in the examples below. Treat it like a password — anyone who has it can use your server.
  • New created keys (best for local use): on the Create API Key tab, after admin login, you can create separate keys, one per app or user, and revoke any of them. Created keys are stored in a keys.json file on the machine running the server, so they work fully when the wrapper runs locally (or on a host with a permanent disk). On Vercel and other serverless hosts that file can be wiped on restart or redeploy, so created keys may stop working there — that is why the online deployment uses the one fixed key instead.
  • Either way, using a key is identical: send it as Authorization: Bearer YOUR_API_KEY (or x-api-key: YOUR_API_KEY) with your POST /api/chat request — see the steps and copy-paste examples below. A wrong or revoked key gets 401.

If DuckDuckGo limits your hosting provider's IPs (chat returns 418, or fails/hangs even though the key is accepted): the problem is the route, not your key. Set DUCK_PROXY in the server's environment variables to a proxy address (for example a residential proxy, http://user:pass@host:port) and redeploy/restart — all of this server's DuckDuckGo requests then go through that proxy, so DuckDuckGo sees the proxy's IP instead of the host's. Optional tuning: DUCK_FETCH_TIMEOUT_MS (per-request timeout, default 20000) and DUCK_CHAT_BUDGET_MS (total chat budget, default 90000). The server logs mark every DuckDuckGo step ([duck] step=…) so you can see exactly which step fails.

Link your key to your own website, app, or server in four steps:

  1. Your server address (base URL) is the address of this server: (loading…) When you deploy this wrapper (e.g. to Vercel or Render), this becomes your deployed address — the examples below update automatically to wherever this page is served from.
  2. Send a POST request to the chat endpoint: POST /api/chat
  3. Send your key in the header — either as Authorization: Bearer YOUR_API_KEY or as x-api-key: YOUR_API_KEY — with Content-Type: application/json and a JSON body like {"message": "Hello", "model": "gpt-5.4-mini"}. The model field is optional: older names like gpt-4o-mini are aliases for the current models, and if you leave it out the default model is used.
  4. Read the JSON reply: {"status": "success", "model_used": "gpt-5.4-mini", "requested_model": "gpt-4o-mini", "reply": "Hello! How can I help?"} Use the reply text in your site or app. If the key is wrong or revoked, you get 401 with an error message instead.

Personal deployments — key optional: if this server was started with ALLOW_KEYLESS_CHAT=true, the API key is not required at all — your app can call POST /api/chat with just the server address and no key header, like a private wrapper only you use (for example, your own app that only knows your Render address). Sending a valid key still works exactly as above; sending a wrong key still gets 401, so leave the header out entirely to chat keyless. Note: with keyless chat on, anyone who knows the server address can use it — personal use only.

Change the AI model — from your own site or app

You choose the model from your external side, on every request — there is nothing to change on this server. Just set the "model" field in the JSON body you send to POST /api/chat:

How model changing works — step by step

  1. You pick a model in your own site or app and put its id in the "model" field of your POST /api/chat request, e.g. {"message": "Hello", "model": "claude-haiku-5-5"}.
  2. The request reaches this server (this wrapper) together with your API key, which the server checks first.
  3. The server checks the model is valid. If you sent an old name, it is converted to the current model id automatically — e.g. gpt-4o-mini becomes gpt-5.4-mini (see the aliases list below). An unknown model gets a 400 reply listing the valid models.
  4. The server forwards your message + that model to DuckAI (DuckDuckGo) — the model you picked travels with the request.
  5. DuckAI answers using that model and sends the reply back to this server, which passes it on to your site or app.
  6. model_used in the response confirms it — it names the model that actually answered (requested_model echoes what you sent). So to change the answering model, just send a different "model" in the next request — no server restart or redeploy is ever needed.

The JavaScript, Python, Node.js and cURL examples below always show the model selected here, so you can copy one straight into your own site or server.

Image input — send a picture with your message

    
Image input — supported. Send an image with your message and DuckAI will look at it and answer about it. Add an image field to your POST /api/chat body containing a data URL: "image": "data:image/png;base64,...." — or "images": [ ... ] for up to 4 images (PNG/JPEG/WebP/GIF, max 5 MB each). Use a vision-capable model — gpt-5.4-mini, claude-haiku-5-5 and tinfoil/gemma4-31b work; mistral-small-2603 does not accept images and returns a clear 400. Bad image data also returns 400 with the reason. The test box below has an attach button so you can try it right here.

    
Image input — JavaScript (fetch)

    
// In a browser you can read a picked file as a data URL:
const dataUrl = await new Promise(res => { const r = new FileReader(); r.onload = () => res(r.result); r.readAsDataURL(file); });
const resp = await fetch(SERVER + '/api/chat', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ' + API_KEY, 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: 'What is in this image?', model: 'gpt-5.4-mini', image: dataUrl })
});
console.log((await resp.json()).reply);

    
Image input — Node.js (server-side)

    
import fs from 'node:fs';
const dataUrl = 'data:image/png;base64,' + fs.readFileSync('photo.png').toString('base64');
const resp = await fetch(SERVER + '/api/chat', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer ' + process.env.DUCK_API_KEY, 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: 'Describe this image.', model: 'claude-haiku-5-5', image: dataUrl })
});
console.log((await resp.json()).reply);

    
Image input — Python (requests)

    
import base64, requests
with open('photo.png', 'rb') as f:
    data_url = 'data:image/png;base64,' + base64.b64encode(f.read()).decode()
r = requests.post(SERVER + '/api/chat',
    headers={'Authorization': 'Bearer ' + API_KEY},
    json={'message': 'What colors are in this image?', 'model': 'gpt-5.4-mini', 'image': data_url})
print(r.json()['reply'])

    
Image input — cURL

    
# Build the JSON with the data URL in the "image" field (jq shown; any JSON builder works):
jq -n --arg img "data:image/png;base64,$(base64 -w0 photo.png)" \
